# Inspectable execution traces

## Architecture discovered

The canonical `SKILL.md` is a methodology, not an executable investigation engine.
`skills/product-support-investigator/` is generated by `scripts/sync_skill.py`.
Codex uses `codex/SKILL.md`, `agents/openai.yaml`, and `.codex-plugin/`;
Claude uses `claude/CLAUDE.md` and `.claude-plugin/`.
Rovo uses `atlassian/AGENT.md`, `atlassian/rovo-adapter.txt`, the compliance gate,
generated `forge-app/prompts/investigator.md`, and Forge manifests/skill files.
`forge-app/src/index.js` is the read-only Jira evidence action using `asUser()`.
`skill_adapter/server.py` distributes inert skill resources over MCP; retrieval
is explicitly **not** proof that the host applied the skill.
`providers/grafana.py` is a bounded HTTP evidence adapter (historical log tool name
`grafana_mcp`); `scripts/grafana_evidence.py` is its CLI.
Existing `observability/` supplies logging, redaction, context and audit events.
`tests/cases.json` and `tests/EVALS.md` describe behavioral evaluations;
`tests/test_*.py` exercise providers, MCP and observability.
The existing Dockerfile and Compose already include Loki, Promtail and Grafana.
No duplicate observability services were introduced.

## Privacy and interpretation

Private model chain-of-thought is neither requested nor recorded. It is not an
execution audit. Traces contain concise adapter-owned decisions, phase outcomes,
metadata, evidence references and compliance results. No tool arguments, tool
results, Jira descriptions/comments, Grafana responses, source files or exception
messages are captured by the wrappers. Safe summaries are a trusted adapter API:
never pass raw prompts or evidence as a summary. Regex redaction is defense in
depth, not a guarantee that arbitrary prose is anonymous.

Secrets, JWTs, authorization headers, cookies, private keys and common email/phone
patterns are redacted before every sink. Trace redaction cannot be disabled.
`PSI_LOG_RAW_EVIDENCE` does not enable payload logging in the trace wrappers.
Default settings: `PSI_LOG_LEVEL=INFO`, `PSI_LOG_FORMAT=json`,
`PSI_LOG_DESTINATION=stdout`, `PSI_ENVIRONMENT=local`,
`PSI_REDACT_SENSITIVE_DATA=true`, `PSI_LOG_RAW_EVIDENCE=false`.
MCP stdio reserves stdout for protocol frames and writes JSON logs to stderr;
Docker captures both streams. Ordinary application hosts use stdout.

## Schema and adapter API

The authoritative versioned dataclass schema is `observability/trace/schema.py`.
Version 1.0 has these top-level fields:

```text
schema_version, trace_id, correlation_id, investigation_id, timestamp,
request_type, request_summary_safe, skill_id, skill_version, skill_applied,
skill_decision_reason, decision_confidence, phases, instruction_checks,
tools_considered, tools_called, tools_skipped, evidence_summary, hypotheses,
read_only_mode, writes_attempted, writes_completed, writes_blocked, write_reason,
user_authorization_present, final_status, final_confidence, errors, duration_ms, events
```

`skill_version` is the canonical SKILL.md SHA-256. IDs are generated UUIDs;
trusted hosts can supply correlation/investigation IDs to `request_trace`.
ContextVars propagate them through async calls and isolate concurrent requests.

```python
from observability.trace import request_trace
from observability.tool_calls import logged_tool_call

with request_trace('incident_investigation') as r:
    with r.phase('collect_issue_context', 'Expected and actual behavior recorded'):
        pass  # perform the actual bounded collection here
    r.skip('github', 'No deployment or code-change signal')
```

Adapters classify requests from their explicit operation contracts. Only
`incident_investigation` and `support_investigation` apply the skill; conceptual,
documentation, how-to, unrelated coding, distribution and startup requests skip it.
This is deterministic routing, not a natural-language intent classifier. A future
chat orchestrator must supply a classified request type; importing a skill cannot
show what the host model did. Decision started/completed events are always emitted
at instrumented request boundaries. Decision confidence is null unless known.

Phases: classify_request, decide_skill_usage, collect_issue_context,
identify_service, identify_time_window, select_tools, retrieve_evidence,
classify_evidence, test_hypotheses, produce_findings, calculate_confidence,
validate_final_response. Each stores status (passed/failed/skipped/not_run), start
and completion timestamps, safe summary, evidence references and error type.
Use `r.phase` to measure actual execution; `complete_phase` is an explicit
completion attestation. Unobserved phases remain not_run. Process termination
leaves an incomplete snapshot rather than inventing successful completion.

Tools record name, server, operation, reason, status, duration, result count when
known, exception type, numeric error code and propagated IDs. Arguments are omitted.
Use `logged_tool_call` for sync/async calls, `r.consider` for selections and `r.skip`
for intentional skips. Existing provider calls and MCP dispatch are instrumented.
Evidence records source, safe locator, observed/inferred/unknown, safe summary,
confidence and optional timestamp. Hypotheses record ID, tested outcome,
evidence references and concise summary. No free-form internal reasoning is needed.

## Compliance and read-only behavior

`observability/trace/evaluator.py::CHECKLIST` maps ten required checks to the
canonical skill's Investigation Principles, Workflow, Hypotheses, Output Contract
and Final Quality Gate. It evaluates recorded completions, tool-selection reasons,
evidence classification, tested hypotheses with references, confidence and explicit
response-check attestations. Missing completion evidence fails an applicable check.
Skipped-skill requests skip investigation-only checks. This checks execution evidence;
it cannot prove the semantic truth of a model's findings or independently verify
adapter attestations. Full completion also requires every phase to be passed/skipped.

Read-only is the default. `r.write(reason, authorized=True)` still blocks unless
`r.trace.read_only_mode` was explicitly disabled. Attempts, blocks, failures and
completions produce audit events. No current Forge action performs writes, and no
new mutation scopes were added. Future Jira comments/updates must use this boundary
(or the equivalent Forge audit contract) before invoking the mutation.

## Local storage and inspection

SQLite stores sanitized snapshots after each event, defaulting to
`.psi-traces/traces.sqlite3` (gitignored). Set `PSI_TRACE_DB` to override it.
Directories/files are created with 0700/0600 permissions; the store uses parameterized
queries and closes connections after transactions.

```sh
python3 -m observability.trace list
python3 -m observability.trace inspect TRACE_ID
python3 -m observability.trace export TRACE_ID --format json
python3 -m observability.trace --db /path/to/traces.sqlite3 list
python3 -m observability.trace.examples --output /tmp/psi-example-traces
```

Inspection includes the complete schema and an explicit incomplete_phases list.
Three checked-in examples in `examples/traces/` are synthetic fixtures: a completed
investigation, a skipped general question, and a failed Grafana call. They are not
claims about a live service or a completed production investigation.

Retention is manual for development: stop writers and delete the SQLite database
(and any SQLite sidecars). Delete exported JSON separately. No automatic expiry is
configured for the existing Loki filesystem store. To delete development telemetry,
stop the stack and remove its specific Loki volume; `docker compose down -v` removes
all stack data, including Grafana settings and trace history. Do not use it when
that data must be retained. Production requires an explicit retention policy.

## Docker, Loki and Grafana

```sh
docker compose up -d --build
docker compose logs product-support-investigator
docker compose exec product-support-investigator python -m observability.trace list
```

Reuse an existing Grafana when available. On this workstation it is
`grafana-local` at **https://localhost:3000**, with its own credentials. Connect it
to the Compose network and provision a Loki datasource pointing to
`http://loki:3100` (see `ops/grafana/provisioning/datasources/loki.yml`). The existing
Grafana is not reset or replaced. If no Grafana exists, explicitly start the bundled
instance with `docker compose --profile standalone-grafana up -d`; it opens
http://localhost:3000 with local development credentials admin/admin and automatically
provisions Loki. Promtail reads Docker logs through
the Docker socket. No host `/var/lib/docker/containers` mount is needed. Only Product Support Investigator containers are selected. Service,
environment and level labels are extracted; IDs remain JSON fields. The socket
mount is required for local discovery; use a constrained collector setup in production.
The existing collector version was retained; upgrading it is outside this change.

```logql
{service="product-support-investigator"} | json
{service="product-support-investigator"} | json | event_type="skill_decision_completed"
{service="product-support-investigator"} | json | status="failed"
{service="product-support-investigator"} | json | tool="grafana_mcp"
{service="product-support-investigator"} | json | trace_id="trace-123"
```

## Platform limitations

Forge uses AsyncLocalStorage and the same field/phase/check contract in
`forge-app/src/trace.js` and `trace-contract.json`. It logs action decisions and every
Jira GET without changing action results, scopes or asUser identity. Jira context
collection is observable; Rovo's subsequent hypothesis testing and final response
are not. Those phases remain not_run with failed compliance checks. Forge snapshots
are in Forge JSON logs, not the local SQLite database; no cloud exporter or remote
collector is configured. Deployment and live Jira/Rovo permissions must be tested
in an authorized Atlassian installation.

Claude/Claude Code and Codex hosts can call the neutral recorder API and ingest
explicit structured tool activity where available. Host verbose output is auxiliary,
not authoritative proof of application execution. Commands, file edits and tests
outside this project's controlled boundaries are not intercepted. A host adapter
should wrap those operations with `logged_tool_call` using a fixed safe operation
label, and should not log raw commands, file contents or test output. Portable skill
bundles without `observability` retain their existing uninstrumented fallback.

```sh
.venv-mcp/bin/python -m unittest discover -s tests
node --test forge-app/src/trace.test.mjs
python3 scripts/validate_skill.py
```

timeouts even when local unit tests pass; report and verify that distinction.
